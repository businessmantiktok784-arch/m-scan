# Stage 3.1 Implementation Report — External point-cloud import

Date: 2026-11-06 · Scope: software only (no device/Blender in sandbox)

## Verdict

**Implemented, unit/integration tested off-device, checks clean.**
`pointcloud_import` is the only Stage 3 operation registered as IMPLEMENTED.
On-device and Blender acceptance remain open (see
[stage3.1-test-results.md](stage3.1-test-results.md)).

## What was built

- **Validators** (pure, streamed, no react-native imports):
  `src/pointcloud/{validate,ply,xyz,las}.ts` — six distinct verdicts,
  1 MiB chunking, cancellation between chunks, `checked_bytes` accounting,
  filename sanitization. PLY header window `max(chunkSize, 4096)` so tiny
  chunks cannot truncate header parsing.
- **Import service** (`src/pointcloud/import-service.ts`) — the only
  expo-facing module: document picker, preflight gates (extension, LAZ early
  reject, 2 GB cap, 200 MB free-space headroom), register-before-copy,
  preserved copy, streamed validation, atomic finalize, cleanup on failure.
- **Database** — migration v3 adds `processing_operations` +
  `pointcloud_imports`; `src/database/import-repository.ts` implements the
  lifecycle over an injectable structural `RepoDb` (expo-sqlite on device,
  bun:sqlite in tests). Success writes the `assets` row in the same
  transaction as the `succeeded` flip; failed/cancelled/interrupted imports
  never register as assets. No FK from imports to assets (documented).
- **Contracts** — `src/models/import.ts`; `pointcloud-asset` widened to
  **v1.3** (backward compatible): `coordinate_units` gains `"unit_unknown"`,
  `coordinate_convention` gains `"source_documented"`, optional
  `original_filename` and `content` block. Imports always record
  `unit_unknown` / `source_documented` / `scale_status UNKNOWN (basis none)`
  with an explicit detail string. Operation registry v1.4: pointcloud_import
  IMPLEMENTED with failure modes incl. `unsupported_variant`,
  `file_too_large`, `insufficient_storage`, `import_interrupted`,
  `source_missing`; TS↔JSON mirror test-enforced.
- **UI** — `app/(tabs)/export.tsx`: import card with staged progress and
  cancel, expandable point-cloud asset rows with real metadata,
  `reconcileInterruptedImports()` on mount, honest PLANNED label for export.
- **Blender add-on v0.2.0** — genuine PLY import (pure parser
  `core/ply_parser.py` + sidecar reader `core/asset_meta.py` + real
  operator); coordinates as stored, colours best-effort, provenance
  sidecar → custom properties; `analyze_mesh` stays a stub.
- **Fixtures** — 26 committed synthetic files regenerated by
  `tests/fixtures/pointclouds/generate_fixtures.py` (face-element header
  bug fixed) with documented exact values. They are test fixtures, never
  presented as mining data.

## Issues found and fixed during the stage

1. Fixture generator emitted face rows without declaring the face element —
   fixed and all 26 fixtures regenerated.
2. PLY header parse failed on 1-byte chunk reads — header window now
   `max(chunkSize, 4096)`.
3. Blender parser bound face-element properties to the vertex element after
   any vertex declaration (list-property false error) and silently misread
   vertex-not-first files — element tracking rewritten; vertex-not-first is
   now `unsupported_variant`, matching the mobile validator.
4. `RepoDb` structural mismatch with expo-sqlite's overloaded statement
   types — explicit `toRepoDb` adapter in the import service.
5. TS control-flow false negatives (`xyz.ts` firstBad narrowing to `never`,
   `ply.ts` circular inference on the binary carry buffer) fixed with a
   widening helper and an explicit annotation.
